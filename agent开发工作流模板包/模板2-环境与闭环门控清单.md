## 3. Agent 基础设施

- [ ] `AGENTS.md` 就位：指向宪章 + 常用命令（测试/lint/部署）+ 目录地图 + 禁区
- [ ] `CONSTITUTION.md` 就位（模板0）
- [ ] `NOTES.md` 就位：agent 跨会话笔记格式约定（进度/决策索引/坑）
- [ ] `/specs` `/docs/adr` `/plans` 目录就位
- [ ] hooks/自动化：保存后自动 lint、提交前自动跑快测（如可用）
- [ ] 沙箱与权限策略：agent 可写的目录白名单、禁止的网络/命令清单
- [ ] 并行护栏（若计划多 agent）：文件/目录所有权矩阵、串行区声明（如 DB migration、package.json 只允许单点修改）

## 4. 可观测性（阶段 4 的"眼睛"）

- [ ] agent 的每次任务执行有日志落盘（`/plans/logs/`）
- [ ] e2e 失败时自动产出截图+视频+trace
- [ ] checkpoint 报告模板就位（见模板4）

## 5. 干跑验证（Dry Run）

用一个**最小真实任务**（如：加一个健康检查端点）完整走一遍：
`领任务 → 写失败测试 → 实现 → 全量验证 → 部署 → 截图自证 → checkpoint 报告`

- [ ] 干跑全程无人工介入
