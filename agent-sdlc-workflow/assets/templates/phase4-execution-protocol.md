# 模板 4：Goal/Auto 长程执行协议

> 阶段 3 确认的 Todo、AC 与 Phase 门控共同构成一个 goal。除真正阻塞外，Agent 连续执行到 goal 完成，不在每张任务卡后等待用户。

## 自主执行循环

```text
读取宪章、spec、计划、NOTES
→ 领取依赖已满足的下一任务
→ 建立失败/基线证据 → 实现 → 局部验证 → 必要 review/ADR
→ 写简短 checkpoint/NOTES
→ 继续下一 ready 任务
→ Phase 门控全过后自动进入下一 Phase
→ Todo 全部完成后进入最终验收
```

## 自主范围

- 当前 goal 内需要的仓库文件可直接读写，影响区域不是权限白名单。
- 具体实现、代码组织、测试组合和可逆取舍由 Agent 根据仓库判断。
- checkpoint 用于可见性和恢复，不是例行审批点。
- 多 Agent 只协调真实写冲突；某任务阻塞时继续其他 ready 任务。

## 规范遵循

每项任务按宪章采用的 SDD/TDD/Review/ADR 和验收规则执行。若某实践在具体任务不适用，Agent 在 checkpoint 简述理由，不需要逐次请示。

跨会话或长程任务使用 `plans/logs/TEMPLATE-checkpoint.md`。单会话任务的最终验证摘要就是 checkpoint；普通文件差异由版本控制提供。

## 验证节奏

- 连贯改动完成后跑最短局部检查，不在每次编辑后跑全套。
- 任务或批次结束跑受影响回归；Phase 退出跑相关集成、契约与关键路径。
- Goal 完成确保最后一次代码变化后有完整/发布级绿色证据；若最近的任务或 Phase 门控已经等同或覆盖它，直接引用该结果。
- 共享契约、schema、权限、安全、依赖、全局配置、并发、迁移或基础设施变化时提前扩大范围。
- 代码与验证输入未变化时复用最近绿色证据；相同失败不再提供新信息时先换假设，不反复回测。

## Spec 回流与用户介入

实现发现规格错误时：`暂停受影响任务 → 记录新事实 → 提 spec delta → 更新影响分析`。还有独立任务时继续执行。

只有以下问题阻断关键路径且无安全替代任务时才集中请求用户：

- 目标、非目标或 AC 必须改变；
- 需要新的外部权限、付费服务或生产/真实数据操作；
- 操作破坏性、难恢复或超出已授权工作区。

普通测试失败、漏列文件、等价重构、实现选择和首次诊断不请求用户。失败不再产生新信息时更换假设或标记局部阻塞，不机械重复。

## Goal 完成

完成全部 Todo 后自动使用阶段 5 模板：

- 对照每条 AC 收集证据；
- 确认所有 Phase 退出门控通过；
- 确认最后一次代码变化后的完整测试、构建或发布级门控为绿色；允许复用等价或更强的最新结果；
- 审计 spec、实现、测试和关键 ADR 一致；
- 明确处置未完成项并沉淀真正可复用的经验。

以上全部满足才报告 goal 完成。
