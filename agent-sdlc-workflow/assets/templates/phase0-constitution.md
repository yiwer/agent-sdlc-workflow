# 项目宪章（CONSTITUTION）

> 定位：本文件是项目的最高治理文档，对所有后续阶段、所有会话、所有 agent 生效。
> 原则：只写**不可变**的东西。技术方案、任务计划不进宪章。宪章修订需走 §7 的程序。

## 1. 不可变原则

| # | 原则 | 含义 |
|---|------|------|
| P1 | Spec 优先 | 任何代码变更必须先有对应 spec（或 fast-track 简版 spec），不允许"先写代码后补文档" |
| P2 | 无验证不完成 | 任何任务完成的标准 = 其退出门控全部通过，且证据（测试报告/截图/日志）落盘 |
| P3 | 决策落 ADR | 所有架构与关键技术决策以 ADR 形式记录于 `/docs/adr/`，含被否决的备选方案及理由 |
| P4 | 至少一轮 review | 所有代码合入前经过至少一轮独立 review（人审或独立 agent 审，不可自审） |
| P5 | TDD | 测试先行：验收标准 → 失败测试 → 实现 → 重构。例外须在本文件登记 |
| P6 | 小步合入 | 单次变更控制在一次专注上下文可完成的粒度；禁止大爆炸式提交 |

## 3. Agent 行为准则

### 3.1 自主边界（可以直接做的事）
- 在任务卡声明的文件范围内读写代码
- 运行测试、lint、构建、本地部署
- 修复自己引入的失败

### 3.2 升级条件（必须停下来问人的事）
- 需求/规格存在歧义或与现有 spec 冲突
- 同一门控连续失败 ≥ 3 次
- 涉及破坏性操作：删库、改生产配置、force push、删除未跟踪文件
- 需要引入宪章未批准的新依赖 / 新服务
- 验收标准本身被发现是错的（走 §6 回流流程，而不是"灵活执行"）

## 5. 目录与资产约定

```
/specs        # 需求规格（当前状态，唯一事实源）
/specs/changes  # 进行中的变更提案（含 delta：ADDED/MODIFIED/REMOVED）
/docs/adr     # 架构决策记录
/plans        # phase 规划与任务卡
/tests/e2e    # playwright 验收测试
NOTES.md      # agent 跨会话结构化笔记（进度、坑、待办）
AGENTS.md     # agent 操作手册（指向本宪章 + 常用命令）
```

## 6. Spec 回流（变更控制）

执行中发现 spec 错误/过期时的唯一合法流程：
1. **停**：暂停相关任务，不得"灵活绕过"
2. **记**：在 `NOTES.md` 与偏差记录中写明冲突点
3. **改**：更新 spec（delta 标记）+ 必要时补 ADR
4. **审**：人确认变更
5. **续**：按新 spec 继续执行

## 7. 宪章修订程序

- 任何阶段可提出修订提案；阶段 5 复盘是例行修订窗口
- 修订需写明动机（哪次失败/漂移暴露了现行原则的不足）
- 修订后人确认生效，历史版本留档
