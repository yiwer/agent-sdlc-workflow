# 模板 5：验收与沉淀

## AC 验收

| AC | 结果 | 证据 | 未完成处置 |
|---|---|---|---|
| AC-1 | pass/fail/deferred | __ | __ |

## 一致性检查

- [ ] spec、实现和测试描述同一行为
- [ ] 关键架构决定有 ADR，普通实现细节没有被过度文档化
- [ ] 未完成项已明确延期、降级或拒绝
- [ ] 若涉及部署/数据，高风险恢复和运行要求已验证

## 复盘

1. 哪个假设最晚才被证伪？
2. 哪个验证回路最有价值，哪个只是制造等待？
3. 哪次用户打断本可由模型判断或已有证据避免？
4. 有什么经验值得自动化或写入长期规则？

只沉淀会重复使用的内容。没有新知识时记录“无变更”，不强制制造宪章或模板更新。

## 关闭门控

- [ ] 承诺 AC 有结果和证据
- [ ] 没有未处置的目标漂移或高风险问题
- [ ] NOTES 留有最终状态与后续入口
