## 自动反馈命令

| 回路 | 命令 | 使用时机 | 通过标准 | 实测耗时 |
|---|---|---|---|---|
| 局部检查 | | 每轮连贯改动后 | | |
| 受影响回归 | | 任务/批次完成 | | |
| 相关集成/契约 | | Phase 退出 | | |
| 关键路径 E2E | | Phase 或风险触发 | | |
| 完整/发布级门控 | | Goal 完成；必要时提前 | | |
| build/package | | Phase/Goal 按需 | | |
| 本地运行/部署 | | canary 与验收 | | |

- Web 项目优先验证 Playwright 能覆盖关键路径；不要求每张任务卡都重复完整 E2E。
- 非 Web 项目选择能从用户或系统边界证明行为的等价验收器。
- 测试应支持按模块、标签或路径过滤；把昂贵反馈放在 Phase/Goal 边界。

完整回归提前触发条件：共享契约、schema、权限、安全、依赖、全局配置、并发、迁移或基础设施变化；或者局部测试暴露影响面超出原判断。

若受影响回归在当前项目中已经等同于完整套件，并且之后没有代码或验证输入变化，它同时满足 Goal 最终门控。

## 闭环干跑

用最小工程 canary 执行。它可以是骨架、探针或极薄的 tracer bullet，用来证明工具链闭环，不要求提前开发正式产品功能：

```text
读取 spec/AC → 建立失败/基线证据 → 实现 → 局部验证
→ 受影响回归 → 独立 review → 本地运行/部署
→ 关键路径自证 → checkpoint
```

记录人工介入点；能通过合理默认值、文档或自动化消除的介入应在进入阶段 3 前消除。

## 退出门控

- [ ] 宪章采用的工程实践均有可执行办法，调整/N/A 有理由
- [ ] 局部、受影响、Phase 和最终门控命令均可执行，canary 选择了最小充分组合
- [ ] 最小工程 canary 完成完整闭环
- [ ] Agent 无需人类代跑命令或解释普通失败
