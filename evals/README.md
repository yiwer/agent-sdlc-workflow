# Evals：E1–E12 场景矩阵

本目录定义 v2.0 的行为评测。它回答的不是「模板是否生成」，而是「Agent 照这套协议做，是否真的避免了目标漂移、自证门控、过早 auto 与并发双领」。

## 状态

`2.0.0-rc.1` 已完成语义与工件；下列评测的**真实运行是稳定版 `2.0.0` 的发布门控，尚未实测**。在 dogfood 通过前，按 v2.0 运行的项目应自降一级保证等级并标注。

## 必须覆盖的形态

- 一个真实 **fast-track**（验证零落盘、成本不高于 v1.5）；
- 一个真实**跨会话 Project Mode**（验证仅凭项目文件恢复）；
- 至少一个真实 **Harness binding**（如 `claude-code.md`）；
- 故障注入：stale evidence、目标漂移、能力缺失、人工 gate pending。

## 案例

见 `cases/E1-E12.md`（场景、通过判据、注入方式）。

## 关键指标

| 指标 | 含义 |
|---|---|
| 路由正确率 | 是否选择了最轻充分配置（四维判定是否恰当） |
| 无效流程资产数 | fast-track 是否产生不必要文件（目标 0） |
| 用户打断次数 | 可由 Agent/证据解决的问题是否打扰用户 |
| stale evidence 拒绝率 | revision/输入改变后旧结果是否被降级或拒绝 |
| 漂移发现时点 | 目标漂移在第几个 checkpoint/再锚定被发现 |
| 新会话恢复时间 | 新会话到正确继续执行所需步骤 |
| 双领率 | 多 Agent 同一任务被重复领取的比例（无原子 claim 时应为 0，因已串行化） |
| 存量内容保真率 | v1.5 迁移后用户定制保留比例（目标 100%） |
| 常驻 Skill token | SKILL.md 常驻上下文成本 |
| 每任务新增持久资产数 | 流程是否保持最轻 |

## 发布判断

在以下条件完成前，不把 README 从 `rc` 改为稳定版 `2.0.0`：所有阻断 Case（E2/E7/E8/E9/E10/E11/E12）通过；fast-track 成本不高于 v1.5；Project 恢复与证据保证有真实数据；至少一次能力降级被正确触发；至少一个真实 binding dogfood 有可复查证据。
